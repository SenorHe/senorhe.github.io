仿真运行流程：从数据接收到3D还原 (ProcedureSimulationRunTime)

本文档总结了基于提供的 C# 脚本，在 Unity 中使用 GameFramework (GF) 的 ProcedureSimulationRunTime 流程如何接收仿真数据，并将其在 3D 场景中进行创建和动态还原的过程。

一、核心流程概述

仿真播放器在进入 ProcedureSimulationRunTime 流程后，主要执行以下步骤来实现 3D 场景的构建和仿真过程的动态展示：

  1. 初始化阶段 (OnEnter):

    • 注册数据变化监听器 (NLDataManager.Instance.Save.DaoSimulationRunTime.AddDataChangedListener(DoRefresh)).
    • 注册核心模块：数据转换器 (dataConverter) 和事件处理器 (eventProcessor)。
    • 首次实体初始化 (InitializeEntities): 加载场景中预定义或静态的 3D 实体模型。这些通常是场景背景、固定设施等。使用 NLGameFramework.Entity.ShowSyc...Entity 异步加载。
    • 如果处于本地模式 (LocalMode)，立即触发 DoRefresh 以加载和处理仿真数据。

  2. 数据接收与处理 (DoRefresh -> DoInitData):

    • 当监听到仿真数据变化 (例如，从服务器接收到新的仿真JSON串 RuntimeSimualtionJson) 或在本地模式下首次进入时，此方法被调用。
    • 核心数据转换 (dataConverter.LoadAndConvertData 或 NoSerializeFieldStrConvertData):
      • 从指定来源 (本地文件 “simulationProcess2” 或 NLDataManager 中的 JSON 字符串) 加载原始仿真数据。
      • 将其转换为内部定义的 DataConvert.SimulationRunTimeData 结构体 (simulationData)。此结构体包含了仿真总览信息 (起止时间、错误信息)、初始智能体数据 (agent_data) 以及核心的离散时间步长数据 (time_steps)。
    • 数据校验：检查 simulationData.time_steps 是否有效，若无效则提示错误。
    • 重置仿真状态 (DoResetRuntimerSimulation): 初始化播放器内部状态，如当前时间、步长索引、播放速度、暂停状态等。

  3. 动态智能体创建 (DoRefresh -> DoGenrateServerAgent):

    • 在 simulationData 加载完毕后，遍历 simulationData.agent_data 列表。
    • 对于列表中的每个 ServerAgent 数据：
      • 使用 GenerateEntityFactory.Instance.ServerAgentDataConvertSimulationData 将服务器原始的智能体数据转换为客户端实体所需的 SimulationEntityData。
      • 根据转换后的 agentData.entityData.ID (如 70001-AGV, 70002-叉车, 70003-货物)，调用对应的 NLGameFramework.Entity.ShowSyc...Entity 方法异步在 3D 场景中创建这些动态智能体。
      • 创建前会检查实体是否已存在，避免重复创建。

  4. 仿真运行与更新 (OnUpdate):

    • 此方法每帧调用，驱动整个仿真过程的推进。
    • 条件检查: 如果处于暂停状态 (isPaused) 或 simulationData 无效，则不执行更新。
    • 时间推进: 根据 elapseSeconds (逻辑帧间隔) 和 simulationSpeed (播放速率) 更新累计时间 (accumulatedTime) 和总仿真时间 (totalSimulationTime)。
    • 核心步长处理 (AdvanceSimulationSteps):
      • 循环检查当前累计时间是否已达到或超过下一个时间步 (nextStepTime)。
      • 处理当前步长 (ProcessCurrentStep):
        • 获取当前 currentStepIndex 对应的 DataConvert.TimeStep 数据。
        • 事件处理: 遍历 currentStep.events，将每个 EventData 交给 eventProcessor.ProcessEvent() 处理。
        • 展示数据处理: 遍历 currentStep.shows，将 showsData 交给 eventProcessor.processShowData() 处理。这些数据通常包含实体ID、目标位置、旋转、动作等信息。
        • eventProcessor (如 DefaultEventProcessor) 内部会将这些指令通过 GameFramework 的事件系统 (如 NLUtil.Instance.DispatchCustomEvent 发送 DEFAULT_EVENT_PROCESS_MOVE_DATA 等事件) 派发给对应的 3D 实体。
      • 更新到下一个步长：增加 currentStepIndex，从 accumulatedTime 中减去已处理的时间，更新 simulationTime，并调用 CalculateNextStepTime 计算下一个事件触发时间点。
    • 结束判断 (IsSimulationFinished): 检查是否所有时间步都已处理完毕且总仿真时间已达到预设的结束时间。
    • 仿真结束处理 (FinalizeSimulation): 若仿真结束，设置暂停状态，派发UI结束事件。

  5. 实体层面的3D还原 (各 Entity 脚本，如 AGVEntity, ForkliftEntity):

    • 各种智能体实体 (如 AGVEntity, ForkliftEntity) 在其 OnInit 方法中会通过 this.AddCustomEventListener(...) 订阅由 ProcedureSimulationRunTime (通过 eventProcessor) 发出的特定事件 (如 DEFAULT_EVENT_PROCESS_MOVE_DATA, DEFUALT_EVEMT_PROCESS_RAITON_DATA)。
    • 当这些事件被触发时，实体的 OnHandlerMessage 方法会被调用。
    • 在 OnHandlerMessage 中，实体会解析事件参数 (如目标ID、起始/结束位置、朝向、持续时间)。
    • 如果事件的目标ID与实体自身的 SimulationID 匹配，则实体会将其内部状态机 (FSM) 切换到相应的状态 (如 AGVStateMove, ForkliftStateRotation)，并将解析出的数据 (如 AgvStatusData, RationStatusData) 传递给该状态。
    • FSM 的具体状态类 (如 AGVStateMove) 负责执行实际的 3D 变换，如使用 Vector3.Lerp 或其他动画机制在给定时间内移动/旋转实体到目标状态，从而在3D场景中还原出仿真数据所描述的行为。
    • 对于货物 (CargoEntity)，它还处理了附着 (Attach) 到叉车或货架，以及分离 (Detach) 的逻辑，根据父实体和传入数据调整自身在3D世界中的位置和父子关系。

  6. 流程结束 (OnLeave):

    • 清理资源，重置状态，隐藏所有加载的实体，反注册监听器。

二、关键数据流与组件

  • 原始数据源:
    • 本地 JSON 文件 (simulationProcess2.json)
    • 服务器通过 NLDataManager.Instance.Save.DaoSimulationRunTime.RuntimeSimualtionJson 提供的 JSON 字符串。
  • 数据转换器 (ISimulationDataConverter -> DefaultSimulationDataConverter):
    • 负责将 JSON 字符串解析/反序列化为结构化的 DataConvert.SimulationRunTimeData 对象。
  • 核心数据结构 (DataConvert.SimulationRunTimeData):
    • agent_data: List<ServerAgent>，定义了仿真开始时需要动态创建的智能体及其初始状态（ID, 类型, 初始位置, 初始旋转）。
    • time_steps: List<TimeStep>，按时间排序的事件序列。
      • TimeStep: 包含一个时间点 (time) 和在该时间点发生的 events (List<EventData>) 及 shows (List<ShowData>)。
      • EventData/ShowData: 包含了具体操作的指令，如哪个实体 (agent_id/object_id) 执行什么动作 (event_type/type)，以及动作参数 (如 start_pos, end_pos, duration, start_direction, end_direction)。
  • 事件处理器 (IEventProcessor -> DefaultEventProcessor):
    • 接收 EventData 和 ShowData。
    • 解析这些数据，并将其转换为 GameFramework 的自定义事件。
    • 通过 NLUtil.Instance.DispatchCustomEvent 或 NLGameFramework.Event.Fire 派发这些事件。
      • 例如: DEFAULT_EVENT_PROCESS_MOVE_DATA (移动事件), DEFUALT_EVEMT_PROCESS_RAITON_DATA (旋转事件)。
  • 实体创建与管理 (NLGameFramework.Entity / EntityExtension.cs):
    • 提供异步方法 (ShowSyc...Entity) 来加载和显示3D实体。
    • 通过 EntityComponent.ShowEntity 实现。
    • EntityExtension 中的异步加载逻辑通过 TaskCompletionSource 和监听GF的 ShowEntitySuccessEventArgs / ShowEntityFailureEventArgs 实现，并控制全局加载界面的显示/隐藏。
  • 3D实体逻辑 (如 AGVEntity, ForkliftEntity, CargoEntity, AgentEntity):
    • 继承自 EntityBase (最终继承自 GF 的 EntityLogic)。
    • 每个实体拥有自己的 SimulationID。
    • 内部包含状态机 (FSM) 来管理其行为 (如 Idle, Move, Rotation)。
    • 监听来自事件处理器的事件，并根据事件数据驱动FSM状态转换和3D模型的实际变换 (位置、旋转、附着等)。

三、3D还原过程总结

  1. 静态场景构建: InitializeEntities 加载固定场景元素。
  2. 动态场景初始化:
    • DoInitData 加载仿真总数据 simulationData。
    • DoGenrateServerAgent 根据 simulationData.agent_data 创建 AGV、叉车、货物等动态 3D 智能体，并设置其初始位置和旋转。
  3. 动态行为还原:
    • OnUpdate 按时间步读取 simulationData.time_steps 中的 events 和 shows。
    • eventProcessor 将这些数据包转换为针对特定实体的指令事件。
    • 目标实体接收到指令事件后，其内部 FSM 驱动 3D 模型执行相应的移动、旋转、抓取、释放等动作，从而在视觉上还原出仿真过程。

通过这套机制，ProcedureSimulationRunTime 成功地将抽象的仿真数据流转换为生动的 3D 可视化场景和动态过程。
