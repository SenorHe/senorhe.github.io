Unity ECS: SystemAPI 详解

SystemAPI 是 Unity ECS (Entity Component System) 1.0 版本及以后引入的一个核心静态类。它为在 ISystem 实现中与 ECS 世界 (World) 交互提供了一套现代化的、类型安全的、且对 Burst 编译器友好的 API。

主要作用：简化和统一系统内部访问和操作实体 (Entities)、组件 (Components) 以及其他 ECS 相关数据的方式。它旨在取代早期版本中直接使用 EntityManager 或在 ComponentSystemBase 中使用 Entities.ForEach 的许多场景，提供更简洁、更安全、性能也更好的接口。

主要功能及作用

1. 查询实体 (Querying Entities)

SystemAPI.Query 是构建实体查询的入口点，允许你根据组件组合筛选实体并进行迭代。

  • SystemAPI.Query<T1, T2, ...>():

    • 构建查询的起点。泛型参数 T1, T2, ... 指定了查询所需访问的组件类型，通常与 RefRW<C> (读写) 或 RefRO<C> (只读) 结合使用，或者直接使用组件类型 (如 LocalTransform)、DynamicBuffer<E> 或 IAspect。

  • 链式方法 (Fluent API) 来构建查询条件:

    • WithAll<T>(): 实体必须拥有所有指定的组件类型 T。
    • WithAny<T>(): 实体必须拥有至少一个指定的组件类型 T。
    • WithNone<T>(): 实体必须不拥有任何指定的组件类型 T。
    • WithChangeFilter<T>(): 仅迭代那些指定组件 T 在上一帧发生变化的实体（用于优化）。
    • WithDisabled<T>() / WithEnabledUP<T>(): 处理可启用组件 (IEnableableComponent) 的状态。
    • WithSharedComponentFilter<T>(T sharedComponentValue): 筛选具有特定共享组件值的实体。
    • WithOptions(EntityQueryOptions options): 设置查询选项，如 EntityQueryOptions.IncludeDisabled (包含禁用组件的实体) 或 EntityQueryOptions.IgnoreComponentEnabledState。
    • WithEntityAccess(): 在迭代时允许访问实体本身 (Entity 对象)。

  • 迭代查询结果: SystemAPI.Query 的结果可以直接在 foreach 循环中使用，通常配合元组解构来访问组件和实体。

2. 访问组件数据 (Accessing Component Data)

SystemAPI 提供了直接获取、设置和检查单个实体组件数据的方法。

  • GetComponent<T>(Entity entity): 获取指定实体上的组件数据 T。如果 T 是 IComponentData，通常返回一个拷贝。推荐使用 GetComponentRO 或 GetComponentRW。

  • GetComponentRO<T>(Entity entity): 获取指定实体上组件数据的只读引用 (RefRO<T>)。

  • GetComponentRW<T>(Entity entity): 获取指定实体上组件数据的读写引用 (RefRW<T>)。这会自动处理依赖关系。

  • SetComponent<T>(Entity entity, T componentData): 设置指定实体上的组件数据。

  • HasComponent<T>(Entity entity): 检查实体是否拥有指定组件 T。

  • GetBuffer<T>(Entity entity): 获取实体上的动态缓冲区 (DynamicBuffer<T>)，用于读写。T 必须是 IBufferElementData。

  • SetComponentEnabled<T>(Entity entity, bool enabled): 设置实体上可启用组件 T 的启用状态。

  • IsComponentEnabled<T>(Entity entity): 检查实体上可启用组件 T 是否已启用。

  • GetEnabledRefRO<T>(Entity entity) / GetEnabledRefRW<T>(Entity entity): 获取可启用组件的只读/读写引用，并允许检查其启用状态。

3. 访问单例组件 (Singleton Components)

单例组件在整个世界中通常只有一个实例，用于存储全局数据或状态。

  • GetSingleton<T>(): 获取单例组件 T 的数据 (通常是拷贝，推荐使用 GetSingletonRO 或 GetSingletonRW)。

  • GetSingletonRO<T>(): 获取单例组件 T 的只读引用 (RefRO<T>)。

  • GetSingletonRW<T>(): 获取单例组件 T 的读写引用 (RefRW<T>)。

  • SetSingleton<T>(T componentData): 设置单例组件 T 的数据。

  • GetSingletonEntity<T>(): 获取拥有该单例组件 T 的实体。

  • HasSingleton<T>(): 检查是否存在该类型的单例组件。

4. 访问系统和世界信息 (Accessing System & World Information)

  • SystemAPI.Time: 获取一个 TimeData 结构体，包含 DeltaTime, ElapsedTime, TimeScale 等时间信息。
  • SystemAPI.World: 获取当前系统所在的 World 对象。
  • SystemAPI.EntityManager: 获取当前 World 的 EntityManager。虽然 SystemAPI 提供了很多便捷方法，但有时仍可能需要直接使用 EntityManager 进行更底层的操作（如在 OnCreate 中创建实体，或在主线程上进行结构性更改）。
  • SystemAPI.IsPaused: (主要用于编辑器) 检查编辑器是否处于暂停状态。
  • SystemAPI.GetSingleton<BeginSimulationEntityCommandBufferSystem.Singleton>() 等: 用于获取 Entity Command Buffer (ECB) 系统的单例，以便创建 ECB 来延迟执行结构性更改。

5. 依赖管理和安全性 (Dependency Management and Safety)

  • 使用 RefRW<T> 和 RefRO<T>（无论是在查询中还是通过 GetComponentXX）会自动为系统声明对相应组件类型的读/写依赖。
  • 这使得 ECS 的调度器能够正确地安排作业 (Jobs) 的执行顺序，防止数据竞争。
  • RefRW<T> 和 RefRO<T> 强制执行读写规则，有助于在 Burst 编译的代码中安全地访问数据。

SystemAPI 的主要优势

  • 简洁性 (Conciseness): 大幅减少了访问和操作 ECS 数据所需的样板代码。
  • 类型安全 (Type Safety): 在编译时就能捕捉到许多常见的错误。
  • Burst 友好 (Burst-Friendly): SystemAPI 的设计考虑了 Burst 编译器的需求，其方法通常可以被 Burst 高效编译。
  • 自动依赖管理 (Automatic Dependency Management): 简化了多线程编程的复杂性。
  • 可读性 (Readability): 代码意图更清晰。

如何使用

SystemAPI 是一个静态类，所以你可以直接在 ISystem 的 OnCreate(ref SystemState state)、OnUpdate(ref SystemState state)、OnDestroy(ref SystemState state) 等方法内部调用它的方法。
