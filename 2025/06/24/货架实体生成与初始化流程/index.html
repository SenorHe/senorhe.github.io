3D 货架实体生成与初始化流程 (ShelfEntity & ShelfStateCreate)

本文档详细描述了 ShelfEntity (货架实体) 在 Unity 场景中被创建后，如何通过其内部状态机 (FSM) 特别是 ShelfStateCreate 状态，根据配置数据动态生成和初始化其 3D 模型的具体流程。

一、流程概述

当一个 ShelfEntity 被 GameFramework 的实体系统加载并显示 (OnShow) 时，它会初始化一个状态机，并通常以 ShelfStateCreate 作为其初始状态。这个状态的核心职责是读取货架的配置数据，并据此构建出货架的实际 3D 外观。

二、详细步骤

  1. 实体加载与状态机初始化 (ShelfEntity.OnShow):

    • 当 ShelfEntity 的 OnShow 方法被调用时，它会首先执行基类 EntityBase 的初始化逻辑，获取传入的 SimulationEntityData (m_EntityData)。

    • 获取子对象中的 ShelvesManager 组件，该组件负责实际的货架模型生成逻辑。

    • 根据货架类型选择FSM状态:

      • 通过 m_EntityData.entityData.ID 判断货架的具体类型（例如，ID 60006 代表 AGV 货架，其他 ID 可能代表托盘货架、轻型货架等）。
      • 为不同类型的货架创建包含不同状态集合的状态机。所有类型的货架都会包含 ShelfStateCreate 和 ShelfStateNomal。
        • AGV 货架 (ID 60006): 状态包括 ShelfStateCreate, ShelfStateMove, ShelfStateNomal, ShelfStatePickUp, ShelfStatePutDown。
        • 其他类型货架 (如托盘货架 ID 60005): 状态包括 ShelfStateCreate, ShelfStateDispositionGoods, ShelfStateNomal。

    • 启动状态机，并将初始状态设置为 ShelfStateCreate。

  2. 进入创建状态 (ShelfStateCreate.OnEnter):

    • 当状态机进入 ShelfStateCreate 时，OnEnter 方法被执行。

    • 获取配置数据源:

      • 通过 GenerateEntityFactory.Instance.repository.GetSimulationTransform(fsm.Owner.SimulationID) 获取与当前货架实体ID关联的源配置信息。这通常是一个在编辑器中预设的带有货架参数组件 (如 AGV货架位置和大小, 托盘货架基础信息 等) 的 Transform 对象。

    • 根据货架ID选择处理方法:

      • 使用 fsm.Owner.m_EntityData.entityData.ID 来区分不同的货架类型，并调用相应的私有方法处理其特有的配置数据和生成逻辑。
        • ID 60006: 调用 processAGVShelvingData(curTransform)
        • ID 60005: 调用 processdpalletRackData(curTransform)
        • ID 60015: 调用 processdLightRackData(curTransform) (轻型货架)
        • ID 60016: 调用 processdMediumRackViewData(curTransform) (中型货架)
        • ID 60017: 调用 processdSUIHeavyDutyRackViewData(curTransform) (重型货架)

    • 设置 IsGenerateFinish = true; 标志，表示模型参数处理和生成指令已发出。

  3. 具体货架类型的数据处理与模型生成 (以 processAGVShelvingData 和 processdpalletRackData 为例):

    • processAGVShelvingData(Transform curTransform) (AGV货架):

      1. 设置货架模型类型: ShelvesData.ModelType modelType = ShelvesData.ModelType.AGVShelving;

      2. 从 curTransform 上获取对应的参数组件：AGV货架位置和大小 和 AGV货架基础信息。

      3. 从这些组件中读取详细参数，例如：

        • 世界坐标位置 (位置和大小.X, 位置和大小.Y)
        • 离地高度, 货架深度, 单元格宽度, 旋转角度, 层高, 列数 (层数), 单元格数, 单双排信息。

      4. 单位转换: 使用 ConvertToMeters 将从UI读取的厘米(cm)或毫米(mm)单位的尺寸数据转换为米(m)。使用 StringToBool_SingleFalseDoubleTrue 将文本的“单排”/“双排”转换为布尔值。

      5. 构建模型属性 (ModelProperty): 将所有解析和转换后的参数封装到一个 ShelvesData.ModelProperty 对象中。

        (注意：示例中的 new Vector3(0,0,0) 和 Vector3.zero 可能需要根据实际需求调整，前者可能是旋转，后者可能是偏移或实际3D位置)

      6. 调用模型生成器: 使用货架实体自身的 ShelvesComponent (即 ShelvesManager) 的 GenerateMode(modelProperty) 方法，传入构建好的 modelProperty 来实际生成或配置货架的3D网格和结构。

      7. 设置初始变换: 根据读取的位置和旋转数据，设置货架实体在场景中的 localPosition 和 localRotation。

    • processdpalletRackData(Transform curTransform) (托盘货架):

      1. 设置货架模型类型: ShelvesData.ModelType modelType = ShelvesData.ModelType.PalletRack;
      2. 从 curTransform 获取 托盘货架位置和大小 和 托盘货架基础信息 组件。
      3. 读取参数如：单元格宽度、单元格数、层高、货架深度、通道宽度、层数、旋转。
      4. 单位转换: 同AGV货架。
      5. 读取额外数据: 从 curFsm.Owner.m_EntityData.extendsDic (实体数据的扩展字典) 中读取预存的更精确的位置信息，如 topStorageCenterPosition, bottomStorageCenterPosition, topPathCenterPosition, bottomPathCenterPosition。这些数据可能是由更上游的布局工具计算并存储的。
      6. 根据类型文本处理复杂布局:
        • 通过 基础信息.类型.text (如 “两通道”, “两货架，一通道”) 判断具体的布局模式。
        • 对于包含通道的复杂布局，可能会多次调用 ShelvesComponent.GenerateMode 来生成多个货架部分，并调用 CreateAisle (虽然当前代码中CreateAisle是空的) 来生成通道区域。
        • 每个货架部分的 ModelProperty 会使用从 extendsDic 中读取的精确位置信息。
      7. 错误处理: 使用 try-catch 块捕获在读取 extendsDic 或处理参数时可能发生的异常。

    • processdLightRackData, processdMediumRackViewData, processdSUIHeavyDutyRackViewData:

      • 与 processdpalletRackData 类似，分别处理轻型、中型、重型货架的参数读取和模型生成调用。它们也依赖于从各自特定的参数组件 (如 轻型货架位置和大小) 和 extendsDic 中获取数据。

  4. 状态更新与切换 (ShelfStateCreate.OnUpdate):

    • 在 OnUpdate 方法中，检查 IsGenerateFinish 标志。

    • 一旦 IsGenerateFinish 为 true (表示参数处理和模型生成指令已完成)，则将状态机切换到 ShelfStateNomal 状态。

  5. 离开创建状态 (ShelfStateCreate.OnLeave):

    • 重置 IsGenerateFinish = false; 为下一次可能的复用做准备 (虽然在此流程中通常只执行一次)。

三、关键组件与数据

  • ShelfEntity: 货架的GameFramework实体逻辑类。持有 ShelvesManager 和状态机。
  • ShelfStateCreate: 货架状态机中的一个状态，负责货架模型的初始化生成。
  • ShelvesManager (fsm.Owner.ShelvesComponent): 实际执行3D模型生成和管理的组件，拥有 GenerateMode(ModelProperty) 方法。
  • SimulationEntityData (fsm.Owner.m_EntityData): 包含货架的静态ID (entityData.ID) 和可能的扩展参数 (extendsDic)。
  • GenerateEntityFactory.Instance.repository: 提供方法 (GetSimulationTransform) 来获取与货架ID关联的编辑器配置对象 (Transform)。
  • 货架参数组件 (如 AGV货架位置和大小, 托盘货架基础信息 等): 挂载在编辑器配置对象上，存储了用户在编辑器中为该类型货架配置的各种尺寸和属性。
  • ShelvesData.ModelProperty: 一个数据结构，用于封装从各种来源收集并处理后的货架参数，传递给 ShelvesManager 进行模型生成。
  • Helper Utilities:
    • ConvertToMeters: 将不同单位 (cm, mm) 的数值转换为米。
    • StringToBool_SingleFalseDoubleTrue: 将 “单排”/“双排” 文本转换为布尔值。

四、总结

3D货架的生成是一个数据驱动的过程：

  1. ShelfEntity 被实例化。
  2. 其状态机进入 ShelfStateCreate。
  3. ShelfStateCreate 根据货架的类型ID，从预设的编辑器配置对象和实体数据中提取参数。
  4. 参数经过必要的转换和组织后，被封装成 ModelProperty。
  5. ModelProperty 被传递给 ShelvesManager 组件，由其负责实际构建或配置3D货架的视觉表现。
  6. 设置货架的初始世界变换。
  7. 完成后，状态机切换到常规运行状态 (ShelfStateNomal)。

这个流程确保了货架可以根据详细的配置数据在3D场景中被准确地程序化生成。
